# P1 补全 0.3.0 — 实现与边界

基于已合并 PR #3 的 main。用户批准合并 P1 后续批次、提前工具/建造距离，新增普通挥砍范围；暴击率改为每级 +10 个百分点。P2 一次性能力与 P3 世界破坏不在本批。

## 实机反馈更新（2026-09-13）

用户确认：暴击率、普通木剑挥砍范围、工具距离、矿物产量有效。最新消息已更正先前“铜矿无增产”的报告。多重暴击实机无效，按用户决定暂不修正，不能视为验收通过；下文层级公式描述的是现有实现意图。戳刺短剑尚不在普通挥砍范围适配内。PR #4 仍未获合并授权。

## 可测试目录

共 45 项已注册数值天赋（原 21 项 + 本批 24 项）。每级 1 点，默认无限等级。新增：跳跃速度、呼吸容量、击退抗性；红心/魔力星、药水病/负面状态时间；暴击率/多重暴击、普通挥砍范围、发射速度、无敌帧；金币、战利品数量/掉率、矿物/木材/草药/宝石/钓鱼产量、出售/购买/重铸价格；工具和建造距离。

## 数据、网络、界面

- 存档仍为 DataVersion=2；读取旧 v1/v2。新增天赋按同一个实际成本账本保存。
- MeleeRange、ToolReach、BuildReach 支持 CurrentIntensity：null 为使用购买的最大等级，非负整数为当前使用等级，不能超过已购等级。降低、提高、恢复最大强度由服务器验证。调整不退款，不改变等级与开关。
- 协议升级为 3；沿用会话 GUID、状态版本、请求回执、限速、超时只读重同步。增加的是有界意图，不接受客户端提交最终属性或价格。服务端必须装相同版本。
- 新增第三行强度按钮；详情可滚动，操作按钮固定。状态栏显示当前启用等级。保留全局 UI 缩放。
- 固定强度使用已有 decimal 存档字段；超过 decimal 容量时仍可使用无限最大等级模式，无法表示的“最大值减一”操作明确拒绝，不改等级。

## 战斗与恢复

- ModifyWeaponCrit +10 个百分点/级，使用原生物品/投射物暴击快照。达到 100% 时必定一重；每多 100% 多一重，尾数随机。暴击倍率增加 tier−1；原暴击伤害天赋继续增加 0.05/级。例如 200% 暴击 + 暴伤 Lv.10 为 ×3.5。
- 标准 DamageClass 才处理。SetCrit 尊重任何 DisableCrit，不强行让召唤物等不支持标准暴击的攻击暴击。暴击率天赋关闭时不接管其他 MOD 的超额暴击。
- 原生整数暴击快照/伤害及 float/int 上限仍存在；极高等级属性最终受引擎数值容量限制。不会逐重循环或改变天赋等级。特殊 MOD 暴击系统可能需要专用适配。
- 近战范围使用 ModifyItemScale：普通 swing、非 noMelee 的武器/工具可见尺寸与命中同步；独立投射物武器不作虚假的通用放大。
- 投射物速度只在 ModifyShootStats 发射时乘算，AI 可覆盖。无敌帧加到实际受击的原生计时槽；不每帧刷新无敌。
- 跳跃速度在原生 UpdateJumpHeight 计算后乘算。呼吸容量增加不补气，降低仅截断。击退抗性使用 HurtModifiers.Knockback。
- 红心/魔力星使用原生六种常见拾取物及魔力斗篷星，在实际原生 PickupItem 完成后补充增益，不拦截其他 MOD 的拒绝拾取钩子。不把未知 MOD 物品猜成红心。
- 新施加的 debuff 时间 ×0.95^Lv；药水病另乘 ×0.93^Lv，最少 1 帧。只在受影响角色的本地执行，避免服务器/旁观客户端重复缩减网络时长。已有计时不因启停反复缩短；原生更新会使 potionDelay 与药水病计时一致。第三方直接写 buffTime 的效果无法通过 AddBuff 接口覆盖。

## 经济、来源与多人

- NPC 数量/金币在 GlobalItem.OnSpawn 结算，服务器/单人生效；原生 DropAttemptInfo.player 优先，否则 NPC.lastInteraction。这里沿用原生掉落归属，XP 仍按 P0 贡献分摊，两者没有混为一套公式。
- 数量采用概率尾数，Lv.10 为两倍。额外物品带重入保护，不能递归放大。不修改普通拾取、丢弃、箱子转移、制作或开袋产物。
- 世界产量：Player.ItemCheck/PickTile 的调用范围，或服务器真实 TileManipulation 消息发送者，结合 KillTile 之前的 tile 类型。作用域用 finally 恢复；无人归属的爆炸/自然坍塌/第三方直接破坏不猜测玩家。
- 矿物按 TileID.Sets.Ore；木材按原生树干标记；草药按三种原生生长阶段（含种子）；宝石为原生七种（含宝石树）。ResourceAdapters 为未知 MOD 来源保留显式扩展。已放置的资源块再挖也属于采集，当前没有自然生成来源追踪。
- 钓鱼使用 ModifyCaughtFish，只处理实际鱼获，沿用原生 owner-client 钓鱼和背包同步；不声称完整服务端反作弊。成长点数依然来自服务端确认。
- 普通金币出售/购买通过原生最终价格计算后加成；特殊货币跳过。不改变物品本体 value；重铸使用 GlobalItem.ReforgePrice 后仍由原生折扣/取整。高等级买卖差价是已批准独立价格成长的自然结果，没有另加隐藏限制。
- 12 个服务器分类开关控制 NPC 数量/掉率：材料、消耗品、药水、弹药、武器、护甲、饰品、Boss、宝藏袋、坐骑、宠物、MOD 物品，默认开启。它们不改 XP，也不关闭独立的金币和采集天赋。
- 物品以合法堆叠拆分，额外世界物品最多占用当前空闲槽，不覆盖已有掉落。极高等级输出超过 int 数量/原生世界物品槽时无法完整生成；槽耗尽会记录警告，等级不截断。

## 掉率公式与适配范围

使用 `1 - (1 - BaseChance)^(1 + 0.1 × Level)`，不以多掉几件冒充概率。当前只接管精确类型为原生 CommonDrop 的 NPC 规则，原生条件检查和后续链仍由原有 resolver 执行；不改变共享规则对象，也不重复整张掉落表。

BaseChance 为含原生 luck 的单次成功率。根据实际 RollLuck 的“先随机选择分母、再随机取值”算法求概率；不是把幸运误算为两次取最小值。无 luck 的 1% 在 Lv.10 为 1.99%。数学测试逐一比对小分母分布。未知 subclass、自定义保底、选择池、其他规则保持原逻辑。

## 明确待确认／未完成

1. **跳跃高度 +4%/级**：原生 jumpHeight 实为按住跳跃的持续帧数，直接乘它不能保证物理高度精确增加 4%。未注册假效果。候选：接受“跳跃持续时间”语义，或另做实际弹道高度控制；需用户确认。
2. **完整掉率规则适配**：CommonDrop 之外的规则尚未覆盖。不能对未知逻辑保证公式等价；留待逐种正式适配。
3. **多人独立掉落**：原生每人独立宝藏袋/按参与者发放物品，以及 noBroadcast 私有生成暂不增产，保留原始掉落。接收者在 OnSpawn 之后才分配，不能用一人的等级放大全员私有物品，或生成公共额外袋。单人普通宝藏袋可按配置增产。后续需明确每个接收者的独立结算适配。
4. GUI 实际渲染、两台实际客户端、内容 MOD 综合兼容仍需实机验证。P0 多人贡献/多阶段 Boss 测试继续按用户决定暂缓。

上述边界已向用户说明，不能将本版称为无条件完整 P1 或全 MOD 兼容。
