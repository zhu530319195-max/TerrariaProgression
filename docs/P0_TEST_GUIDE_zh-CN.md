# TerrariaProgression P0 0.1.0 安装与验收

## 安装

1. 使用 **tModLoader 稳定版 v2026.07.3.0（Terraria 1.4.4.9）**。它与原版 Terraria 1.4.5、旧版 tModLoader、预览版不是同一目标。
2. 打开 tModLoader → 模组 → 打开模组文件夹，把测试包中的 `TerrariaProgression.tmod` 放进去。
3. 返回游戏，启用 **Terraria Progression**，重新加载模组。联机时客户端与服务器使用同一版本。
4. 首轮用新测试角色和测试世界。成长数据会写入角色，测试添加的经验也会保留。

如果按钮位置不同，常见文件夹为 `%USERPROFILE%\Documents\My Games\Terraria\tModLoader\Mods`；使用 OneDrive 时，以游戏内打开的文件夹为准。

源码包中的 `TerrariaProgression` 文件夹可放入游戏“创意工坊 → 开发模组 → 打开源码文件夹”打开的 `ModSources` 目录，选择构建并重新加载。源码文件夹与 `.tmod` 二选一即可。不要安装仓库 `tests` 目录中的 CI 测试模组。

## 最短单人测试

在模组配置中开启“开发测试命令”，其他参数保持默认。进入新角色后打开聊天，逐条输入：

```text
/tpstatus
/tpgivexp 1000
/tpstatus
```

正常结果：

| 时机 | 等级 | 当前经验 / 下一级需求 | 累计经验 | 可用天赋点 |
|---|---:|---:|---:|---:|
| 新角色 | 1 | 0 / 250 | 0 | 0 |
| 添加 1000 经验后 | 4 | 50 / 490 | 1000 | 3 |

P0 没有正式天赋购买菜单，天赋点只累计，HP、MP、伤害等不会增加。

继续输入：

```text
/tpgivexp 0.05
/tpstatus
```

经验应为 `50.05 / 490`，累计经验 `1000.05`，天赋点仍为 3。

然后让角色死亡、复活、退出重进、换另一世界，再输入 `/tpstatus`；数据应保留。完成后可关闭“开发测试命令”，正常击杀成长仍有效。

## 经验封顶

用另一个新测试角色，在默认配置下输入：

```text
/tpgivexp 10000000
/tpstatus
```

下一级需求应为 `50000`，而且一次增加许多等级，每级给 1 点。把“单级所需经验上限”改为 `0` 后重新查看，同等级需求应高于 50000。修改上限不自动回退已有等级；下次获得经验时按新配置结算。

## 普通击杀与雕像

- 默认倍率下，击杀普通 5 HP 兔子应增加 5 XP；以实际游戏生命为准。
- 普通敌怪按最大生命计经验，即使一击大幅溢出伤害也只产生一次 lifeMax 预算。
- 城镇 NPC 应不给经验。
- 雕像单位分别测试倍率 `0 / 0.5 / 1 / 2`；例如 100 最大生命的单位对应 `0 / 50 / 100 / 200 XP`。
- 出现不足 1 点的小数经验应能累计。
- 击杀后稍等片刻再查询，多实体会等同组战斗结束后结算。

## 双人联机

先在单人给测试角色一些经验，退出单人，再用同一角色加入服务器。入服 `/tpstatus` 的成长应保留，不应回到 1 级。退出联机回到单人也应保留已收到的成长。

两人一起攻击同一个高血量目标：A 先打掉大部分生命，B 最后击杀。两人都应按各自有效伤害分到经验，不能全部归 B。开启“记录经验结算日志”可查看 `server.log` 中的 `XP settlement` 行。

轮流测试近战、弓枪/魔法投射物、召唤物和哨兵。纯持续伤害归属目前有限制，见下方。

普通客户端执行 `/tpgivexp 1000` 必须被拒绝。若用独立专用服务器，且配置已开启开发命令，可在服务器控制台输入（无斜杠）：

```text
tpstatus 0
tpgivexp 0 1000
tpstatus 0
```

这里 `0` 是玩家槽位。Steam“开服并游玩”没有独立控制台时，添加测试经验请先在单人完成。联机客户端不能更改服务器成长规则；请开服前设置，专用服务器则停止后修改 `ModConfigs/TerrariaProgression_ProgressionConfig.json` 并重启。

## 必须人工验收的 Boss 场景

开启结算日志，分别打世界吞噬者、毁灭者，以及自己常用内容 MOD 的多节/多阶段 Boss：

1. 完整击杀，确认同一组只产生一次生命预算，没有几十个身体段各奖一份。
2. A/B 分别打不同身体部位，结束后两人都按贡献分配。
3. 只击杀一部分后让 Boss 脱战消失，不应获得完整 Boss 的结算。
4. 死亡分裂、变身、新阶段出现时，确认没有重复结算。
5. 两只独立同种 Boss 同时存在，不应仅因同类型而合成一只。

## P0 已知限制

- 多实体采用保守的“同组最大 lifeMax 一份”。因此世界吞噬者等独立血条身体段、明确父子来源的随从可能比把每段相加给的经验少；这是通用去重保护，尚未承诺所有 Boss 的最终精确分组。
- 持续伤害没有可靠通用的施加者记录：已有直接贡献者仍按已记录比例分配；不会把未归属 DoT 伪装成最后一击玩家的贡献。完全无归属、无已记录攻击的击杀不发给任意玩家。
- 不走原版玩家命中消息、未提供父子/血条关联的第三方攻击与 Boss 阶段，可能需要明确兼容适配。
- 在最终结算前断线，暂不补发该连接的份额，也不会把份额送给别人。
- 保留跨单人/联机存档需要入服导入角色数据；P0 校验结构和内部一致性，无法证明离线存档没有被手工编辑。入服后经验由服务器结算。
- 云端自动检查不能代替两台真实客户端、Steam 联机与实际 Boss 战。

## 出错时上传什么

请提供报错截图，以及游戏目录 `tModLoader-Logs` 中本次的 `client.log`；联机问题再提供服务器的 `server.log`。同时告诉我 tModLoader 版本、启用的 MOD 名单、出错前输入的命令或攻击方式。

经验异常最好附击杀前后 `/tpstatus` 截图，打开“记录经验结算日志”后复现一次。存档问题还可备份并上传该测试角色的 `.plr` 与 `.tplr`，先不要覆盖原文件。

验收后明确回复“验收通过，可以合并”，才会进行 PR 合并。
