## 范围与分类

新增 BaitSaving、CrateChance，共 81 项：49 个数值注册项＋32 个功能注册项（含十个数值型）。不添加未实现占位天赋。显示分类由 `Core/TalentNavigation.cs` 唯一维护，六类二十组：

| 一级 | 二级 |
|---|---|
| 生存与恢复 | 生命与魔力、恢复与治疗、防御与抗性、环境与异常防护 |
| 战斗与召唤 | 攻击强化、攻击方式、消耗与召唤、异常攻击、受击反应 |
| 移动与探索 | 地面移动、跳跃与攀爬、飞行与游泳、视野与信息 |
| 采集与钓鱼 | 资源采集、钓鱼强化、拾取与收获 |
| 建筑与工具 | 工具效率、建造辅助 |
| 掉落与交易 | 战利品、商店与重铸 |

合计 20 个非空二级分组；以后范围作业有实现后才显示。导航按已注册成员显示非空分组。一级选择显示该类全部，左侧展开当前分类。中栏列天赋，右栏详情及操作；操作区独立滚动，避免小屏挤掉说明。复合天赋的免费子开关仍在详情内。

全局搜索按当前语言名称或内部 ID、不区分英文字母大小写，长度最多80字符，支持原生输入与中文输入法。结果附分类路径。已购买包括关闭的天赋；已启用要求已购、开启且当前强度大于0。筛选只影响展示，不改变退款成员。关闭并重开菜单保留当前会话内的分组、筛选和搜索；未额外写入角色存档。

沿用旧 `TalentCategory` 数字与天赋 ID，既有等级、启停、当前强度、成本段和子开关不迁移或重置。新的 `RefundMenuGroup`、`RefundMenuCategory` 操作使用稳定作用域字符串，由服务器验证成员并原子退款。搜索时退款范围跟随选中结果；分类全部视图的分组退款跟随选中天赋。按钮显示目标组/类名和该范围全部实际支付点数，退款不受搜索/筛选裁剪。旧协议拒绝新目录：协议10，全部端用0.8.0。存档仍v3；AutoJump退休退款继续有效。

## 钓鱼规则

两项1点/级、无限等级、可调当前强度、关闭不退款。

- 鱼饵：原生消耗概率乘 `0.93^L`。`GlobalItem.CanConsumeBait` 概率返回 false，否则 null 交回原生。绝不返回 true 强制消耗，与原生渔具箱和其他 veto 叠加。钓竿、鱼饵、池塘条件保留。特殊合法鱼饵也沿用这条规则。
- 宝匣：原生 `crate=false` 的有效尝试，以 `1−0.95^L` 概率改为 true；已有 true 不重复改、不额外耗随机数。其余字段不改。原生成功概率 p 因而变为 `1−(1−p)×0.95^L`。蜂蜜跳过，岩浆仍有原生额外筛选，敌人、稀有度、环境、困难模式与任务鱼选择都留给原生流程。不直接替换最终鱼获，不重抽整套奖励。
- 例：原生10%宝匣资格在Lv.10变约46.11%；当前原生宝匣药水资格为25%，同级变约55.09%。这些是资格概率，最终鱼获仍取决于后续分支，不能声称每种液体中均为相同比例。
- 两项只在已确认角色的 owner-client 执行，服务器和旁观副本不重复抽取。与已有钓鱼一致，并非新增服务端背包反作弊层。天赋购买、退款和状态仍由服务器确认。

实际入口与顺序依据固定目标 tModLoader v2026.07.3.0 的 Player/Projectile 实现及编译验证。公开文档：[ModPlayer](https://docs.tmodloader.net/docs/stable/class_mod_player.html)、[FishingAttempt](https://docs.tmodloader.net/docs/stable/struct_fishing_attempt.html)。

## 饰品扫描器

开发命令 `tpscanaccessories`（聊天加 /），限启用开发命令后的单人或服务器控制台。枚举已加载 `ContentSamples.ItemsByType` 中 accessory 样本，读取静态名称和已缓存 Tooltip。不会新建 Item 测试对象，不调用 SetDefaults/UpdateAccessory/ModifyTooltips，不反射推理，不读写角色成长。

输出时间戳 JSON＋带 UTF8 BOM 的 CSV 至 `Main.SavePath/TerrariaProgression/Reports`，包含来源、内部名称、当前语言名称/说明、映射状态、天赋ID、实现类型、兼容等级、显式白名单及完整注册表。未加载的另一语言名称填 null，报告明确注明，绝不切换全局语言或伪造翻译。信息饰品识别只依明确映射，不推断未知物品。

状态 Mapped/Partial/Unmapped 表示文档映射，不等于实机验收。组合饰品未审完、能力语义不同或附带额外属性时为 Partial。未知原版/第三方为 Unmapped/X。报告中 Validation 明确“本扫描未执行测试”。基础白名单是已审查来源样本，不声称已完整映射全部原版饰品；其余由报告继续发现。

## 验证与边界

复用旧阶段自动检查并增加：全目录唯一分类、无空/孤立分组、历史成本分组/分类退款、非法范围与跨类保护、中英文/ID搜索、筛选、两项新天赋的强度与存档、原生鱼饵消耗样本、原生鱼获选择样本、药水/渔具箱叠加、禁用和零强度、服务端不重复抽取、真实服务器新退款包、扫描不执行未知测试饰品、JSON/CSV输出验证。最终计数及提交见 PR/CI 和交付包 BUILD_INFO。

实机仍须验收菜单在中文输入法、不同UI缩放下的显示与操作，实际钓鱼和真实多人。旧药水病/钓鱼产量未验收、分层暴击暂缓、特殊/多阶段Boss与多人独立掉落等状态保留。新钓鱼测试不等于旧钓鱼产量验收。

液体移动辅助/蜂蜜强化、电线、执行器、独立跳跃高度移出开发计划；悬停/闪避暂缓。异常伤害强化与更多异常另批，P3未开发，取消自动跳跃/世界宝箱强化继续有效。

### 固定版本鱼饵接口修正
首轮CI34779384504发现原生消耗在启停下完全相同。核查固定版本PlayerLoader实现，CanConsumeBait错误地枚举HookCaughtFish，因此只有覆盖ModifyCaughtFish的ModPlayer才会进入该分派。改用官方GlobalItem.CanConsumeBait，移除ModPlayer同名覆盖，避免未来引擎修复后双重抽取。保持原生实际消耗测试及原有断言。修正提交 `b4d6de949720c2681aa970203e0cc29972658aa4` 在 [CI 34779551529](https://github.com/zhu530319195-max/TerrariaProgression/actions/runs/34779551529) 通过3060项核心检查、431项原生检查，正式MOD与测试MOD编译均零警告、零错误。

固定随机种子的原生样本：8000次鱼饵消耗尝试，未强化消耗885、Lv.10消耗460；装备渔具箱时815、叠加Lv.10时424。6000次普通水域原生鱼获选择，未强化宝匣608、Lv.10为2791；宝匣药水1472、药水叠加Lv.10为3305。这是自动运行证据，不代替玩家实机验收。

## 0.8.1 客户端加载修复

玩家实测0.8.0加载失败：TalentUISystem.Load → Activate → TalentUIState.OnInitialize → RefreshTalents → GetModPlayer，在角色组件表尚未建立时越界。原专用服务器回归不会自动加载标为Client的TalentUISystem，因而此前431项原生通过不等于客户端加载通过。

0.8.1的Load仅注册按键；首次在世界内打开时才创建UI，使用原生TryGetModPlayer确认角色组件已建立。OnInitialize仅构造布局，不读取角色数据；首个Update按当前角色状态刷新。主菜单、死亡、专用服务器与未就绪角色不能打开，退出世界/卸载安全关闭。存档v3、协议10和81项天赋保持不变。

新增原生回归手动调用客户端系统Load，并使用空的原生ModPlayer数组复现旧GetModPlayer异常，检查延迟创建、未就绪访问拒绝、就绪/死亡/服务器条件和未打开时退出。测试不需要显卡或字体资源，也不代替完整客户端显示与交互验收。中文指南新增重启、重新启用MOD、首次开菜单、切换角色和再次启动步骤。
