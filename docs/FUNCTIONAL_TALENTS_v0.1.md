# TerrariaProgression — 功能天赋正式规格 v0.1

> 状态：正式设计基线。用于 P2 功能天赋、功能效果注册器、饰品候选扫描器以及第三方 MOD 兼容实现。
>
> 本文件补充 `docs/PROGRESSION_DESIGN_v0.1.md`。若两者对功能天赋存在冲突，以本文件较新的明确规则为准。

## 1. 设计目标

功能天赋不是简单增加伤害、生命或资源倍率，而是让角色永久获得原版饰品、信息配件、环境能力或其他特殊机制，而无需占据正常饰品栏。

基本原则：

1. 一次性功能天赋（`U`）默认统一消耗 **2 天赋点**。
2. 购买后永久解锁到角色存档。
3. 已解锁功能可以随时开启/关闭。
4. 关闭不返还点数。
5. 回退/洗点返还实际支付的 2 点，并重新锁定该功能。
6. 数值型功能继续使用 `N` 或 `N+T`，默认无限升级，不强行改成一次性解锁。
7. 功能天赋不依赖真实装备槽，不要求玩家把对应饰品放入背包或装备栏。
8. 优先使用 tModLoader/原版稳定状态与子系统；只有必要时才桥接实际饰品逻辑。
9. 未知第三方 MOD 饰品绝不自动变成正式可购买天赋。

---

## 2. 功能效果实现层级

所有功能天赋通过统一 `FunctionalTalentRegistry` 注册。具体效果按可靠性分五类。

### 2.1 `NativeFlag`

直接使用 Terraria/tModLoader 已有的玩家状态、布尔标志或稳定属性。

适合：

- 无坠落伤害
- 水上行走
- ~~自动跳跃~~（P2-A实机反馈后取消，旧购入自动退款）
- 部分环境免疫
- 部分信息显示

优先级：最高。

优点：实现简单、兼容性高、联机状态容易控制。

### 2.2 `NativeSystem`

使用 tModLoader 正式提供的专用系统，而不是手写模拟。

适合：

- `ExtraJump` 多段跳
- 冲刺/移动子系统（若存在合适稳定接口）
- 飞行/翅膀相关正规状态
- 其他具有独立生命周期的原生机制

优先级：高。

### 2.3 `AccessoryBridge`

创建/引用可信的原版饰品效果，并复用其功能逻辑，但不真正占据装备槽。

仅用于：

- 没有稳定 `NativeFlag` / `NativeSystem` 的原版功能；
- 已确认调用后不会额外附带不需要的数值；
- 已通过单人和联机实机测试的功能。

默认规则：

- 只桥接明确白名单中的原版饰品；
- 同一种特殊效果默认不与真实装备重复叠加；
- 如果真实饰品已经提供该效果，天赋效果视为“已满足”，而不是再执行一次；
- 组合饰品不得未经拆分直接作为天赋来源，以避免一次获得多个未购买能力。

### 2.4 `Custom`

Terraria 没有适合直接复用的入口时，由 TerrariaProgression 自己实现。

适合：

- 自定义无限飞行逻辑
- 特殊受击触发
- 高级视野/显示效果
- 需要明确服务器权威的复杂能力

必须单独写测试。

### 2.5 `Composite`

一个天赋由多个已注册子效果组成。

适合：

- 全信息显示
- 十字章式异常免疫集合
- 多个简单生存功能的组合包

`Composite` 只组合稳定的已知效果，不扫描运行时未知饰品。

## 3. FunctionalTalentRegistry 数据合同

建议每个功能天赋至少注册：

- `TalentId`
- `DisplayNameKey`
- `DescriptionKey`
- `Category`
- `TalentType` (`U` / `N` / `T` / 组合)
- `DefaultCost`
- `ImplementationKind`
- `DefaultEnabled`
- `VanillaSourceItemId`（可选）
- `ChildEffects`（Composite 可选）
- `StackPolicy`
- `ConflictPolicy`
- `NetworkAuthority`
- `CompatibilityGrade`
- `RequiresServerPermission`
- `Experimental`

### 3.1 默认堆叠规则

对于布尔/功能效果：

`StackPolicy = SatisfyOnce`

即效果存在即可，不因为真实饰品 + 天赋同时存在而重复执行。

对于以后明确允许叠加的能力，必须逐项声明，不能默认叠加。

### 3.2 兼容等级

- `A`：NativeFlag / NativeSystem，优先实现。
- `B`：经过验证的原版 AccessoryBridge。
- `C`：Custom，实现可靠但需要专项测试。
- `X`：未知或第三方实验能力，不进入默认正式目录。

## 4. 正式功能天赋目录

## 4.1 移动与机动

### 数值型（无限升级）

这些不是 2 点一次性解锁，而继续按照数值天赋规则成长：

| 天赋 | 类型 | 当前默认 |
|---|---|---|
| 多段跳 | N+T | 每级 +1 次最大额外跳跃，实际启用次数可调 |
| 飞行时间 | N+T | 每级 +1 秒，实际启用强度可调 |
| 飞行速度 | N+T | 每级 +5% |
| 游泳速度 | N+T | 每级 +10% |
| 跳跃高度 | N | 见主设计文档 |
| 跳跃速度 | N | 见主设计文档 |

### 一次性功能（统一 2 点）

- 无坠落伤害
- ~~自动跳跃~~（P2-A实机反馈后取消，旧购入自动退款）
- 冲刺
- 攀墙
- 滑墙/墙面缓降
- 冰面防滑/冰面抓地
- 水上行走
- 岩浆表面行走
- 无限飞行（不消耗飞行时间；与“飞行时间”数值天赋并存）
- 悬停/稳定滞空模式（若实现可靠）

说明：

- 无限飞行是独立开关能力，不删除飞行时间天赋；玩家可自行决定是否启用。
- 冲刺只实现一种 TerrariaProgression 标准冲刺，不自动复制所有第三方盾牌/饰品冲刺。
- 多段跳等级决定最大跳数，玩家可把实际跳数调低。

---

## 4.2 环境与生存

一次性功能，统一 2 点：

- 水下无限呼吸
- 岩浆完全免疫
- 炽热方块/火焰方块免疫
- 液体移动惩罚减免/取消（若实现稳定）
- 蜂蜜移动强化（若实现稳定）
- 危险感知
- 陷阱感知
- 黑暗视野强化/夜视
- 角色自发光（可独立关闭）

数值型环境能力继续独立存在：

- 最大呼吸容量
- 游泳速度
- 环境伤害减免（若以后加入数值成长）

---

## 4.3 信息功能

为了避免菜单被大量“手表/罗盘/深度计”条目淹没，默认采用一个组合天赋：

### 全信息显示

- 类型：`U + T + Composite`
- 默认价格：2 点
- 解锁后允许逐项开关显示内容，不额外收费。

默认包含可可靠实现的原版信息：

- 时间
- 深度
- 东西方向/罗盘
- 天气
- 月相
- 渔力/钓鱼信息
- 附近敌人数
- DPS
- 稀有生物探测
- 金属/矿物探测
- 宝藏探测
- 击杀计数
- 雷达/附近生物信息

原则：

- 玩家只购买一次“全信息显示”。
- 内部 UI 可以关闭不想看的信息。
- 不为每一块原版信息饰品分别收 2 点。

---

## 4.4 异常状态与控制免疫

### 异常状态免疫

- 类型：`U + T + Composite`
- 默认价格：2 点
- 目标：覆盖原版十字章/十字章护盾体系中适合永久化的常规负面状态免疫。
- 解锁后允许逐项关闭某些免疫，不额外收费。

预计覆盖：

- 中毒
- 流血
- 缓慢
- 虚弱
- 破甲
- 沉默
- 诅咒
- 混乱
- 黑暗
- 寒冷/冰冻相关常规负面状态
- 燃烧等常规可免疫状态

### 击退免疫

- 类型：`U + T`
- 默认价格：2 点
- 与“击退抗性”数值天赋并存。

原因：完全免疫击退会彻底改变手感，因此单独作为功能开关；玩家若不想完全免疫，可关闭它并使用数值型击退抗性。

说明：

- 不承诺自动免疫第三方 MOD 自定义 Debuff。
- 第三方 Debuff 只有通过明确兼容注册后才加入集合。

---

## 4.5 建筑与工具辅助

### 数值型（无限升级）

- 建造距离：每级 +1 格
- 工具使用距离：每级 +1 格
- 放置速度：后续作为数值天赋加入
- 墙壁放置速度：后续作为数值天赋加入
- 材料节约率：若加入，使用概率/衰减型数值模型

### 一次性功能（统一 2 点）

候选正式能力：

- 自动喷漆/建筑喷漆辅助
- 自动执行器/执行器建筑辅助（实现可靠后启用）
- 建筑标尺/格线辅助显示
- 电线/机关辅助视图（若实现不会破坏原版权限）

这些功能优先使用原版 Builder/Grand Design 类能力拆分后的单独功能，而不是整件组合饰品一键桥接。

---

## 4.6 钓鱼与采集便利

### 数值型

- 钓鱼产量
- 宝匣概率
- 鱼饵节约
- 草药产量
- 木材产量
- 矿物产量

### 一次性功能（统一 2 点）

- 钓线不断
- 熔岩钓鱼资格/允许在岩浆中正常钓鱼（实现可靠后）
- 一键伐木（若最终作为解锁型；也可以继续归 P3 模式能力）
- 自动补种（若最终作为解锁型入口；范围/效率仍可单独数值成长）

---

## 4.7 战斗触发效果（归战斗分类，不塞进普通功能页）

以下属于“饰品特殊效果”，但 UI 上应归入战斗类，避免功能页无限膨胀。

候选：

- 受击召唤星落/星星反击
- 受击释放蜜蜂/蜂群
- 受击获得短时移动加速
- 受击触发特定反击效果
- 攻击附加燃烧
- 攻击附加中毒
- 攻击附加其他原版 Debuff

规则：

- 纯开关型触发效果：`U + T`，默认 2 点。
- 带概率、伤害、数量的效果：优先拆成 `N + T`，让数值可重复升级。
- 不直接桥接大型组合饰品，以免附带额外属性。

### 闪避

闪避更适合作为数值型战斗天赋，而不是 2 点获得固定概率：

- 类型：`N + T`
- 具体每级概率另行确定
- 需要服务器/伤害判定侧可靠实现

---

## 4.8 库存、拾取与便捷功能

已经存在的数值天赋：

- 物品拾取范围
- 金币获取
- 战利品数量

后续可评估的功能候选：

- 自动收集特定物品类别
- 自动把特定掉落发送到特定容器/储存系统
- 自动使用/补充建筑材料

这些不属于原版简单饰品效果，默认不进入 v0.1；只有在不会与 Magic Storage 等第三方系统产生明显冲突时再设计。

## 5. AccessoryTalentScanner — 候选扫描器

## 5.1 目标

扫描器是**开发工具**，不是玩家自动导入器。

用途：

- Terraria 更新后发现新增原版饰品；
- 检查现有饰品是否存在尚未登记的特殊功能；
- 给开发者输出候选清单；
- 减少人工遗漏。

## 5.2 扫描范围

扫描已注册 Item/ModItem 元数据，并尽量收集：

- Item ID / Mod 名称
- 中文/英文显示名
- 是否 Accessory
- 是否信息类饰品
- Tooltip/描述
- 是否已经有 `FunctionalTalentRegistry` 映射
- 已知来源类型（原版 / 第三方）
- 候选兼容等级

输出示例：

```text
[Unmapped Vanilla Accessory]
Item: Lucky Horseshoe
Candidate: FallDamageImmunity
SuggestedImplementation: NativeFlag
RegistryStatus: Missing

[Mapped]
Item: Obsidian Skull
Candidate: HotTileImmunity
RegistryStatus: HotTileImmunity
```

## 5.3 扫描器绝不做的事情

扫描器不得：

- 自动扣除天赋点；
- 自动向玩家菜单加入未知功能；
- 自动执行未知第三方 `UpdateAccessory`；
- 自动用反射修改未知 `ModPlayer`；
- 根据 Tooltip 文本直接生成正式逻辑；
- 自动断言两个不同饰品一定是同一种效果。

候选必须经过人工确认和实机验证后才能进入正式 Registry。

---

## 6. 不采用“反射差分自动推理饰品效果”

明确不把以下方案作为正式功能：

1. 创建测试 Player。
2. 记录全部字段。
3. 应用饰品。
4. 比较字段差异。
5. 自动推断效果。
6. 自动创建天赋。

原因：

- 许多能力只在受击、攻击、跳跃、液体环境、按键等事件发生时才生效；
- ModPlayer 私有/自定义状态无法可靠推断语义；
- 一次字段变化可能是组合饰品多个效果共同产生；
- 第三方 MOD 可能依赖装备槽、Item 实例、网络状态或其他隐藏条件；
- 自动推断极易生成看似能用但实际不完整的天赋。

因此仅保留“候选扫描”，不做“效果自动推理”。

## 7. 第三方 MOD 饰品兼容

默认配置：

`ExperimentalImportedAccessories = false`

正式支持模式：

### 7.1 明确兼容

针对常用 MOD，可增加手写兼容模块：

- 明确 TalentId
- 明确来源能力
- 明确调用方式
- 明确冲突/叠加规则
- 有实机测试证据

### 7.2 实验导入

未来可提供实验性“尝试桥接 MOD 饰品”功能，但必须：

- 默认关闭；
- 明确标注“不保证所有 MOD 饰品生效”；
- 不自动进入正式天赋目录；
- 失败不得影响角色存档或导致服务器崩溃；
- 服务端可以完全禁止。

### 7.3 不承诺万能兼容

TerrariaProgression 的正式兼容目标是：

- 原版能力优先完整支持；
- tModLoader 标准 API 能自然兼容的第三方内容尽量自动兼容；
- 第三方复杂饰品采用明确适配，而不是承诺“任何 MOD 饰品都能永久化”。

---

## 8. 冲突与重复效果规则

功能天赋默认遵循：

### 8.1 Boolean/状态功能

真实装备已经提供效果时：

- 不重复应用；
- UI 仍显示天赋已解锁/已开启；
- 卸下真实装备后，天赋继续提供效果。

### 8.2 数值功能

必须明确：

- `Add`：与装备加算；
- `Multiply`：与装备乘算；
- `Max`：取更高值；
- `Replace`：天赋覆盖；
- `NoStack`：存在一个即可。

未声明时不允许自行猜测。

### 8.3 Composite

组合天赋内部每个子效果仍独立判断冲突，不能因为组合能力存在就强制重复执行所有来源。

---

## 9. 联机与服务器权威

以下能力必须特别检查多人：

- 冲刺/特殊移动
- 闪避
- 受击触发
- 攻击附加效果
- 无限飞行
- 世界交互功能
- 自动补种/一键伐木

规则：

- 只影响本地视觉/UI 的能力可客户端执行；
- 影响伤害、状态、世界、掉落或玩家位置合法性的能力必须尊重服务器权威；
- 服务器可关闭实验第三方桥接；
- 世界修改能力继续受 `MaxBlocksPerAction` 和服务器总开关保护。

## 11. UI 原则

功能页按子组显示：

- 移动
- 环境
- 信息
- 异常免疫
- 建筑/工具
- 钓鱼/采集

战斗触发效果仍显示在“战斗”页，而不是普通功能页。

每个一次性功能显示：

```text
无坠落伤害
状态：已解锁 / 未解锁
价格：2 天赋点
当前：开启 / 关闭

[解锁] 或 [启用/关闭]
[回退并返还2点]
```

组合能力（全信息、异常免疫）额外提供：

`[配置子效果]`

用于逐项打开/关闭内部功能，不再额外消耗天赋点。

## 12. 当前正式结论

TerrariaProgression 不追求“扫描所有饰品并自动永久化”。

正式路线是：

`已知原版能力 → Registry 明确注册 → 优先原生 API → 必要时白名单桥接 → 实机验证 → 成为正式天赋`

开发扫描器只负责：

`发现未登记候选 → 输出报告 → 人工确认`

第三方 MOD：

`标准 API 自然兼容 + 常用 MOD 明确适配 + 实验桥接默认关闭`

## 13. P2-B 0.5.0 实现细则
用户已批准移动、建筑与钓鱼便利这一批。九项均为2点一次解锁：冲刺、攀墙、滑墙、无限飞行、冰面防滑、建筑标尺／格线、自动喷漆、钓线不断、熔岩钓鱼。
